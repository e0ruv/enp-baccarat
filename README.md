# ENP BACCARAT — 가상 머니 모의 바카라

실제 화폐를 사용하지 않는 **가상 머니 전용** 바카라 시뮬레이터입니다.
실제 라이브 바카라(Stake · Evolution `Korean Speed Baccarat`)의 모바일 세로 화면 구성을 기준으로
**딜러 스튜디오 · 출목표 · 베팅 매트** 3단을 한 화면에 담았습니다.

## 실행

정적 사이트입니다. 폴더를 그대로 열거나 로컬 서버로 띄우면 됩니다.

```bash
cd baccarat-sim
python3 -m http.server 8000
# http://localhost:8000
```

## 디자인 기준 (실물 테이블 화면 맞춤)

- **폰트**: 모든 UI·숫자·버튼·배지·결과창은 고딕 산세리프 한 가지(`Pretendard` → `Apple SD Gothic Neo` →
  `Noto Sans KR` → 시스템 산세리프)로 통일합니다. 테이블 바닥에 희미하게 인쇄된 `PLAYER` / `BANKER`
  워터마크만 얇은 세리프를 유지합니다.
- **테이블**: 베이지-브라운 펠트, 검정/흰색 엣지 스팟 카지노 칩(매트 위 칩).
- **베팅 매트**: 플레이어 로열 블루 · 무 에메랄드 아치 · 뱅커 크림슨. 이름은 칸 하단 중앙,
  `무`는 `무 8:1` 한 줄, 사이드 베팅은 이름/배당 2줄 중앙 정렬.
- **점수 배지**: 점수가 없을 때 반투명 회색, 점수가 나면 선명한 파랑/빨강 각진 라운드(6px).

## 화면 구성

### 1단 · 딜러 스튜디오
- **실사풍 딜러 일러스트**(`assets/dealer.png` / 경량 `assets/dealer.jpg`)가 스튜디오 상단에 테이블과
  자연스럽게 이어집니다. 좌우는 같은 이미지의 블러 배경, 상단·하단은 그라데이션으로 녹입니다.
  벚꽃·눈꽃·스피드 테이블별 색조 틴트가 얹힙니다.
- 가상 테이블(`PLAYER` | `BANKER`, 우측 슈).
- 베팅 중: 우측 상단 원형 **10초 카운트다운** — **0초가 되면 자동으로 베팅 마감 · 딜링 · 정산**.
  마지막 5~3초는 금색으로 빛나고 3초부터는 붉게 맥동하며, 크기·z-index를 올려 어떤 요소에도 가리지 않습니다.
- **딜러 손 모션**: 흰 장갑을 낀 딜러의 손이 테이블 뒤에서 내려와 오른쪽 카드 슈 입구에서 카드를
  뽑아 포물선으로 `PLAYER` / `BANKER` 자리까지 끌고 가 내려놓고 물러납니다. 슈 입구가 빛나고
  카드가 뒤집히며, 손과 카드는 카드 크기에 맞춰 모바일·데스크톱 모두 같은 비율로 움직입니다.
- 카드가 놓일 때마다 **좌·우 점수 배지가 그 자리에서 바로 합산**(`(합계)%10`)되어 7 → 3 → 7처럼 실시간으로 바뀝니다.
  쪼기 모드에서 뒷면인 카드는 더하지 않고, 열리는 순간 더해집니다.
- 정산 후 하단 중앙(점수 배지 사이)에 **승리 진영 원형 배지**(`P` 파랑 / `B` 빨강 / `T` 초록 + `PLAYER WIN` 등)가
  링 파동과 함께 뜹니다. 결과 시트는 **이겼거나 푸시일 때만** 뜨고, 잃은 라운드는 승리 배지만 보여줍니다.
- 결과 표시가 끝나면 **테이블의 카드·미니 카드·점수 배지·승리 배지가 모두 사라지고** 새 10초 카운트다운이 시작됩니다.
- 벚꽃·눈꽃 테이블은 상단에 보너스 카드 레일(**매 라운드 7장**, ×2~×8)이 표시됩니다.
  배당은 낮은 값 위주(×2 약 35% · ×3 약 29% · ×4 약 18% · ×5 약 12% · ×8 약 6%)이고,
  슈 카드와 맞춰 주는 보조 확률은 12%만 섞어 과하게 터지지 않습니다.

### 2단 · 출목표 (Evolution 실물 화면 f_06 · IMG_1309 그대로 · 항상 보임)
- 흰 바탕(`#ffffff`) + 연회색 격자선. **첫 판 전에도 빅로드 6행 · 중국점 1·2·3군 · 우측 비드로드의
  빈 셀 격자가 모두 그려져** 실제 출목표처럼 보입니다.
- **빅로드**: 6행 격자에 **글자 없는 굵은 속 빈 링**(플레이어 `#1565c0` · 뱅커 `#c61923`).
  타이는 링을 가로지르는 초록 대각선(`/`), 페어는 링 테두리에 붙는 작은 점
  (플레이어 페어 = 좌상단 파랑 · 뱅커 페어 = 우하단 빨강).
- **중국점 1·2·3군**: 라벨 없이 빅로드 **바로 아래에 간격 없이** 3등분으로 붙고, 행 높이는 빅로드의 절반.
  칸은 빅로드 칸의 절반 크기라 모바일에서도 약 **16~20열**이 보이고, 새 마크가 생기면 오른쪽 끝을 넘지 않고
  최신 열로 밀려서 표시됩니다.
  1군은 속 빈 작은 동그라미, 2군은 속 찬 점, 3군은 대각선 빗금 — 모두 파랑/빨강.
- **중국점 진행 규칙(Evolution/마카오 표준)**: 타이를 뺀 **매 판 하나씩** 마크가 늘어납니다(같은 쪽 연승 중에도 멈추지 않음).
  1군은 빅로드 2열 둘째 칸부터, 2군은 3열 둘째 칸부터, 3군은 4열 둘째 칸부터 시작하고, 새 열 첫 칸은 직전 두 열 길이가
  같으면 빨강·다르면 파랑, 열 아래로는 비교 열 길이와 현재 행이 같으면 파랑·아니면 빨강입니다. 같은 색은 아래로,
  6행 바닥이나 이미 찬 칸이면 오른쪽으로 꺾이고, 색이 바뀌면 새 열로 갑니다.
- **비드로드**: 오른쪽에 **큰 솔리드 원형 배지 + 굵은 흰색 `P`/`B`/`T`**. 최신 열이 빅로드 쪽(왼쪽)에서
  선명하게 채워지고 지난 열은 흐려집니다. 좁은 모바일에서도 2열이 꽉 차게 보입니다.
- **접기/펼치기(`^`)**: 통계줄이 아니라 **빅로드 우측 상단 안쪽(비드로드 왼쪽)**에 떠 있는
  반투명 흰 원형 버튼. 누르면 중국점을 접어 빅로드를 넓게 봅니다.
- **통계줄**: `0%` 알약 · `#26` · `P 12` `B 12` `T 2`(진영 색 원형 배지) · Ask-the-road 알약
  `P ○●/` `B ●○/` — 영상과 같은 둥근 배지 스타일. 세 점은 중국점 **1군·2군·3군의 마지막 마크**로,
  그 진영이 다음 판에 이겼다고 가정했을 때의 색(빨강 `r` / 파랑 `b`)을 그대로 보여 줍니다.
- **Ask the road**: `P`/`B` 버튼(터치 영역 46×25)을 누르면 다음 판이 그쪽으로 끝났다고 가정했을 때의
  빅로드 다음 칸이 **화면 안에서 굵게 점멸하는 링**으로 표시되고, 중국점 1·2·3군이 시작된 뒤에는
  해당 칸들도 함께 점멸합니다(4초 뒤 자동 해제, 다시 누르면 전환).

## 당첨 연출 (IMG_1308)

- 이기면 테이블 위에 **영상과 같은 당첨 연출**이 뜹니다: 상단을 가로지르는 얇은 그라데이션 리본
  (뱅커=빨강 · 플레이어=파랑 · 무=초록) → 그 아래 `이겼습니다` → **금빛 글로우 `₩` 당첨 금액**
  (그 라운드 총 지급액) + 금빛 반짝이. 결과 시트 팝업은 띄우지 않고 이 연출만 보여 줍니다.
- 당첨된 베팅 칸의 칩은 **당첨 금액대의 칩 색**으로 빛나며 `97K+`처럼 금액이 표시됩니다
  (칸 오른쪽 아래, 카드·이름을 가리지 않음).
- 하단 정보 바의 `총 베팅금` 자리가 **`지난 우승 ₩97,500`**(금색)으로 바뀌고, 다음 라운드가 시작되면
  `총 베팅금`으로 돌아옵니다.
- 벚꽃·눈꽃 배당이 붙은 승리는 기존 배수 뱃지(`×40`)·벚꽃/눈 낙화 연출이 함께 나옵니다.

## 칩 (IMG_1309 그대로)

금액은 칩 안에서 영문 단위 **`K`(천) · `M`(백만) · `B`(십억)** 로 표시합니다 — 매트 위 베팅 칩,
당첨 칩, 트레이 위 `칩 10K` 표기 모두 같은 규칙입니다(`chipLabel` / `winChipLabel`).
글자는 길이별 `ln2`·`ln3`·`ln4`·`ln5` 클래스로 크기를 줄여 **작은 원(솔리드 중앙 원 지름의 60%) 안에** 들어갑니다.

| 칩 | 색 | 칩 | 색 |
|---|---|---|---|
| `1K` | 회색 `#8E949C` | `500K` | 보라 `#7B3FA8` |
| `5K` | 핑크 `#E86BA8` | `1M` | 골드 `#B98F27` |
| `10K` | 빨강 `#C62828` | `5M` | 남색 `#1B3A6B` |
| `50K` | 초록 `#1B8A3A` | `10M` | 청록 `#0E8C9E` |
| `100K` | 검정 `#1E1E20` | `100M` | 마젠타 `#C2187A` |

- **구조**: 색상 몸통 + 상·하·좌·우 4방향에 각각 **2줄씩 흰색 스트라이프 블록** + 얇은 흰 안쪽 링 +
  솔리드 중앙 원 + **굵은 흰색 산세리프 금액 글씨**. 선택한 칩은 얇은 금빛 외곽 링으로 강조합니다.
- 매트 위 베팅 칩과 당첨 칩도 같은 모양·같은 금액대 색을 씁니다.
- 베팅 금액 제한은 없습니다 — **보유 잔고 안에서는 한 칸·총 베팅 모두 얼마든지** 걸 수 있고, `100M` 칩을 여러 장
  쌓아 10억을 넘겨도 칩 배지는 `1.1B`처럼 B 단위로 이어집니다. `½`·`2×` 칩도 잔고까지만 커집니다.
- 기본 가상 머니 **₩10억**, `충전`은 누를 때마다 +₩10억(무료).

## 자동 진행 (실제 라이브 테이블 방식)

- 베팅 카운트다운 **10초**가 0이 되면 자동으로 베팅이 마감되고 카드 딜링 → 정산 → 결과 표시 → 테이블 정리 →
  새 10초 카운트다운 순서로 끊김 없이 이어집니다.
- **베팅하지 않고 관전만 해도 슈가 계속 돌아가며 출목표가 쌓입니다.** (관전 라운드는 결과 시트·사운드 없음)
- 베팅한 뒤 기다리기 싫으면 기존 **`딜` 버튼**으로 즉시 딜할 수 있습니다.
- 로그인/회원가입 · `6160` 관리자 · 규칙 모달이 열려 있거나, 탭이 백그라운드이거나, 셔플 중일 때는
  카운트다운과 자동 진행이 **일시정지**되고 모달을 닫으면 이어집니다.
- 쪼기 모드에서 카드를 열지 않고 20초가 지나면 자동으로 전체 오픈되어 슈가 멈추지 않습니다.
- 결과 표시는 스피드 2.3초 · 벚꽃/눈꽃 2.7초(빅윈 +1.2초)이며, 그동안은 베팅이 잠기고 끝나면 테이블이 비워집니다.
- **8덱 슈(416장)가 끝나면 자동 셔플 후 새 슈로 이어지고, 출목표는 새로 시작**합니다(누적 손익·전적은 유지).

벚꽃·눈꽃 테이블에서는 위 사이드 베팅에도 보너스 카드 배수가 곱해집니다.
정산은 모두 `js/engine.js`의 `settleRound()`가 담당하고, UI는 그 결과만 표시합니다.

## 기능

- **베팅 금액 이동**: 칩이 놓인 칸을 **길게 누르거나(0.38초) 끌어서** 다른 칸에 놓으면 금액이 그대로 옮겨집니다.
  (모바일 터치 · 데스크톱 마우스 모두) 잔액 변화 없이 이동만 기록되며 `↺` 실행 취소로 되돌릴 수 있습니다.
- **한 번의 탭 = 한 번의 베팅**: 베팅 칸은 `pointerup`에서만 베팅하고, 직후 브라우저가 합성하는 `click`은
  700ms 동안 무시합니다(모바일 이중 베팅 방지). 의도적인 빠른 2연타는 두 번 모두 베팅됩니다.
- **더블탭 확대 방지**: `viewport`에 `maximum-scale=1, user-scalable=no`, 인터랙티브 요소 전부에
  `touch-action: manipulation`(베팅 매트는 `none`), 핀치·더블탭 기본동작 차단. 상단 로고 더블탭 `6160` 관리자는 그대로 동작합니다.
- 칩 `1K`~`100M`, ½·2×, 되돌리기 · 초기화 · 재베팅, 스피드 자동 재베팅
- 쪼기(Squeeze) 모드: 카드를 탭해서 한 장씩 오픈, 전체 오픈 버튼(20초 뒤 자동 오픈)
- 라이브 배수: 카드가 공개될 때마다 매칭된 보너스 카드 위에 금빛 `4x` 배지·카드 테두리 점등, `⚡ 플레이어 ×40` 칩 표시
- 빅윈 연출: 배수 승리 시 골드 연출 + `+₩` 배너
- 출목표: 빅로드 · 중국점 1·2·3군 · 비드로드 · 통계 · 최근 기록(데스크톱)
- Web Audio 합성 사운드 (칩·카드·당첨·테마음), 음소거 지원
- 계정: 아이디 + PIN 회원가입/로그인, 게스트 즉시 플레이, 계정별 잔액·기록 저장(localStorage)
- 히든 관리자: 로고 더블클릭/더블탭 → PIN `6160` → 회원 목록, 잔액 +/−·초기화, GitHub 동기화(선택)
- 반응형: 모바일 세로(390×844) 3단 단일 화면 / 데스크톱(1440×900) 좌우 2단

## 참고

- 모든 금액은 가상 머니입니다. 충전은 무료이며 실제 결제가 발생하지 않습니다.
- 계정·잔액·기록은 브라우저 localStorage에만 저장됩니다. (서버 없음)
- GitHub 동기화는 관리자에서 리포지토리(`owner/repo`)와 PAT를 입력해 사용합니다.
  PAT는 이 기기의 localStorage에만 저장되며, `baccarat/users.json` 경로로 올리고/불러옵니다.
